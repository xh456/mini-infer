## 附：测量纪律

1. **同一硬件、同一软件版本**才能横向对比。换卡之后所有基线作废，必须重测。
2. 先 warmup 再计时，第一次运行包含权重加载与 kernel 自动调优，不代表稳态。
3. 用 `torch.cuda.synchronize()` 卡住异步执行的边界，否则测的是"下发命令的时间"。
4. 贪心解码（`do_sample=False`）+ 固定随机种子，去掉采样带来的抖动。
5. **报告最小值，而不是平均值。** 噪声几乎只会让结果变慢，不会变快，所以最小值是对
   "这台机器能做到多快"最稳的估计。同时必须报告离散度——只给一个数字等于隐藏了不确定性。
6. **出数前先确认机器是静的。** 记录 `loadavg`，阈值 1.0。2026-10-16 的实测表明：
   宿主负载高时，同一配置跨运行差异可达 70%~100%，单次运行内部离散度超过 1000%。
   这种数字没有任何比较价值，写进报告只会误导自己。正式基线加 `REQUIRE_QUIET=1`。
7. **同一组对比必须背靠背连测。** CPU 持续满载会降频——测量越久越慢。相隔十分钟的
   两组数字不可比，哪怕硬件和参数完全一样。
